# devops-project

DevOps tooling for an e-commerce app (React TS, Spring Boot, AWS RDS). Application
source lives elsewhere in the repo; this folder only holds infrastructure and delivery.

## Layout

```
ansible/      Playbooks + terraform_runner role that drive Terraform
terraform/    One stack per folder: vpc, eks, rds, s3-cloudfront
helm/         spring-boot-backend chart
```

## Terraform state and wiring

- State is stored in S3 (`subhadeep-terraform-state-bucket`, eu-north-1) with native
  locking (`use_lockfile`, Terraform >= 1.10). Each stack has its own key:
  `devops-project/<env>/<stack>/terraform.tfstate`.
- Backend settings live in `terraform/<stack>/environments/<env>.backend.hcl`.
- Stacks read each other through remote state, so no IDs are copied by hand:
  `vpc` -> `eks` (VPC + private subnets) -> `rds` (VPC, private subnets, EKS node SG).
- The RDS master password is generated by RDS and kept in Secrets Manager
  (`db_master_secret_arn` output). No password exists in the repo.

## Running it

Prerequisites: Terraform >= 1.10, Ansible, AWS credentials, the `aws` CLI (used by the
helm provider to get EKS tokens). Run everything from this folder.

```bash
# plan, then apply, all stacks in order
ansible-playbook ansible/playbooks/01-provision-infrastructure.yml -e tf_action=plan
ansible-playbook ansible/playbooks/01-provision-infrastructure.yml

# destroy (reverse order, asks for confirmation)
ansible-playbook ansible/playbooks/99-destroy-infrastructure.yml
```

Note: `plan` for `eks` and `rds` only works once the stacks they depend on have been applied.

Or run a single stack by hand:

```bash
cd terraform/vpc
terraform init -backend-config=environments/dev.backend.hcl
terraform apply -var-file=environments/dev.tfvars
```

## Argo CD

Installed by `terraform/eks`. It is a ClusterIP service by default:

```bash
aws eks update-kubeconfig --name app-cluster-dev --region us-east-1
kubectl -n argocd port-forward svc/argocd-server 8080:443
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d
```

## Backend Helm chart (`helm/spring-boot-backend`)

- Probes use Spring Boot Actuator (`/actuator/health/liveness` and `/readiness`), so the
  app needs `spring-boot-starter-actuator`.
- The container runs as non-root with a read-only root filesystem (`/tmp` is an emptyDir).
- DB settings: `database.host` (terraform output `db_endpoint`), and credentials from a
  Kubernetes Secret with keys `username` and `password`. Either point
  `database.existingSecret` at one, or set `externalSecret.enabled=true` and
  `externalSecret.remoteSecretId` (output `db_master_secret_arn`) to sync the
  RDS-managed secret via External Secrets Operator. The operator, its IAM role and a
  `ClusterSecretStore` are not installed by this repo yet.
- Never deploy with `image.tag: latest`; CI should set an immutable tag (git SHA).

```bash
helm lint helm/spring-boot-backend -f helm/spring-boot-backend/values-dev.yaml
helm template backend helm/spring-boot-backend -f helm/spring-boot-backend/values-dev.yaml
```

## Frontend (`terraform/s3-cloudfront`)

Private S3 bucket behind CloudFront (origin access control, HTTPS only, managed cache and
security-header policies). 403/404 fall back to `/index.html` so React Router deep links
work. Deploy a build with:

```bash
aws s3 sync build/ s3://<s3_bucket_name> --delete
aws cloudfront create-invalidation --distribution-id <cloudfront_distribution_id> --paths "/index.html"
```
